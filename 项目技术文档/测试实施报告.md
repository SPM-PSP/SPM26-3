# 测试实施报告

# 1. 概述

## 1.1 系统需求概述

“搭子星球——大学生全能搭子匹配平台”项目是基于微信开发者工具开发的微信小程序，旨在为大学生群体构建一站式全场景搭子匹配与社交平台。

### 1. 项目背景

大学生群体普遍具有强烈的社交与结伴需求，但在日常学习生活中面临“找搭子难、兴趣不匹配、时间凑不齐、场景覆盖单一”等突出问题。

现有社交平台或泛社交属性过强、缺乏针对性，或仅聚焦单一场景（如旅行或学习），无法为大学生提供覆盖全日常场景的垂直化搭子匹配服务。

搭子星球以“精准匹配、安全社交、场景全覆盖”为核心理念，致力于打造专属于大学生的搭子匹配社交平台。

---

### 2. 目标用户

平台面向有各类结伴需求的大学生群体，细分为三类核心用户画像：

| 用户类型  | 核心诉求                       | 典型痛点                |
| ----- | -------------------------- | ------------------- |
| 社交娱乐型 | 寻找搭子一起干饭、追剧、逛街、短途旅行，拓展社交圈  | 熟人时间难凑，找不到兴趣相投的陌生搭子 |
| 学习成长型 | 寻找考研、考证、自习、竞赛学习搭子，互相监督共同进步 | 独自学习缺乏动力，找不到同进度伙伴   |
| 运动体验型 | 寻找运动搭子及旅行、探店等体验型搭子         | 独自运动枯燥，户外/旅行结伴有安全顾虑 |

---

### 3. 核心功能需求

系统功能需求围绕五大核心模块展开：

#### （1）首页模块

* 多场景搭子推荐（旅行、学习、干饭、运动等）
* 今日热门结伴帖展示
* 核心功能快捷入口（发布搭子、找搭子、看攻略/经验）
* 全局搜索（按场景、标签、地点、时间筛选）
* 场景分类导航

#### （2）找搭子模块

* 多维度筛选功能（场景、地点、时间、人数、性别、年级、兴趣标签）
* 基于用户画像和需求的智能匹配推荐
* 结伴帖详情查看（发布者信息、结伴要求、具体安排）
* 支持一键申请加入

#### （3）发搭子模块

* 选择结伴场景并填写核心信息（目的地/地点、时间、人数、要求）
* 添加兴趣标签与补充备注
* 支持上传图片
* 发布后可编辑、置顶、关闭结伴帖
* 查看申请列表并筛选通过创建群聊进行聊天

#### （4）动态分享模块

* 多场景内容分类（旅行攻略、学习方法、干饭推荐、运动技巧等）
* 内容创作与分享（发布结伴体验、场景干货）
* 支持图文/文字形式发布
* 热门内容推荐
* 支持收藏、点赞、评论功能

#### （5）我的模块

* 个人信息管理（学生认证、个人资料、兴趣标签、搭子等级）
* 我的结伴管理（已发布、已申请、已成功的搭子帖）
* 我的收藏管理（收藏的结伴帖、攻略/经验）

---

### 4. 非功能需求

#### 性能需求

平台需在多用户并发访问场景下保持响应流畅，匹配推荐、动态加载等核心操作响应时间应在合理范围内。

#### 可靠性需求

系统需保证数据一致性（尤其结伴帖状态同步），提供稳定可靠的 7×24 服务。

#### 可用性需求

界面简洁直观，符合大学生使用习惯，操作流程顺畅，支持多场景便捷切换。

#### 安全性需求

实现学生身份认证机制，保障用户个人信息安全，对结伴帖内容进行合规审核。

#### 兼容性需求

前端微信小程序需兼容主流微信版本，后端服务需支持主流服务器环境部署。

#### 可维护性需求

代码结构清晰、注释规范，采用前后端分离架构便于独立维护与功能迭代。

## 1.2 系统设计与实现概述

### 1. 系统架构

本系统采用前后端分离架构：

#### 前端

微信小程序，使用微信原生开发框架（WXML/WXSS/JS）。

小程序页面包括：

* 登录页
* 首页
* 找搭子页
* 动态广场页
* 动态详情页
* 发布搭子页
* 发布动态页
* 聊天室页
* 消息通知页
* 个人主页等共 21 个页面

采用自定义 TabBar 底部导航：

* 首页
* 找搭子
* 发布
* 消息
* 我的

#### 后端

Java 技术栈，采用 Maven 构建管理。

源码位于：

```text
sourcecode/backend
```

包含：

```text
src/main/java
src/test/java
```

#### 通信方式

前后端通过 HTTP/HTTPS 协议进行数据交互。

前端调用微信登录接口获取用户凭证后与后端完成身份认证。

---

### 2. 功能模块设计

#### 用户模块

负责：

* 用户注册/登录
* 学生身份认证
* 个人资料管理
* 兴趣标签管理

#### 搭子模块

负责：

* 结伴帖发布
* 编辑
* 关闭
* 查询
* 筛选
* 匹配推荐
* 申请管理等核心业务

#### 动态模块

负责：

* 动态内容发布
* 分类展示
* 点赞
* 评论
* 收藏等社区互动功能

#### 消息模块

负责：

* 系统通知推送
* 用户间聊天沟通等功能

#### 搜索模块

负责：

* 全局搜索
* 场景筛选
* 标签匹配等检索功能

---

### 3. 数据存储

后端负责业务数据的持久化存储，包括：

* 用户数据
* 结伴帖数据
* 动态数据
* 消息数据等

前端负责用户会话状态及本地缓存数据的存储：

* 登录态
* 浏览记录等

---

### 4. 关键业务流程

#### （1）登录与首页浏览

用户通过微信授权登录后进入首页，浏览多场景搭子推荐及热门结伴帖。

#### （2）查找搭子

用户可通过多维度筛选：

* 场景
* 地点
* 时间
* 人数
* 性别
* 年级
* 兴趣标签

查找合适搭子，查看结伴帖详情后可一键申请加入。

#### （3）发布搭子帖

用户可选择结伴场景发布搭子帖，填写核心信息：

* 目的地
* 时间
* 人数等

发布后可在“我的”中管理结伴帖状态，查看并筛选申请者。

#### （4）动态互动

用户可在动态广场浏览、发布图文/文字内容，对感兴趣内容进行：

* 点赞
* 评论
* 收藏

#### （5）消息通知

系统通过消息模块向用户推送：

* 申请结果
* 互动通知等信息

## 2. 测试策略

### 单元测试

基于 JUnit 框架对后端 Java 代码进行单元测试。

使用 Apifox 对所有后端 API 接口进行功能验证。

在微信小程序端逐页面、逐功能进行手动测试。

### 兼容性测试

在不同品牌型号手机上进行兼容性验证。

### 性能测试

### 安全测试

| 等级       | 描述       | 处理要求    |

# 2.4 通过准则

## 1. 功能通过准则

1. Critical 及以上等级缺陷全部关闭
2. Major 缺陷修复率不低于 95%
3. 核心业务流程全部正常
4. Minor 与 Trivial 缺陷有明确处理计划

---

## 2. 性能通过准则

1. 核心接口平均响应时间不超过 2 秒
2. 并发用户数不少于 50 时系统稳定运行
3. 无脏读、幻读等一致性问题

---

## 3. 兼容性通过准则

1. 支持至少：

   * 3 款 Android 机型
   * 2 款 iOS 机型

2. 核心业务流程可完整运行，无闪退问题。

---

## 4. 安全通过准则

1. 未登录用户无法访问受限接口
2. 用户只能操作本人数据
3. 敏感信息具备安全保护机制

---

## 5. 文档通过准则

1. 所有缺陷均记录至 GitHub Issues
2. 测试报告完整，包括：

   * 用例执行统计
   * 缺陷分析
   * 测试结论
